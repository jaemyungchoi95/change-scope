# 평가 계획

상태(2026-10-31): T09 축소판 실행 완료. 24개 유형 대응과 holdout 결과는 [평가 결과](evaluation-results.md)에 있습니다. 검색-only 비교와 별칭(유형 9·10)은 미실행입니다.

## 주 검증 경계

하나의 공개 CLI 워크플로를 주 경계로 사용합니다.
검토된 fixture를 적재하고 분석 결과 JSON·Markdown을 만드는 경로에서 실제 PyreWire 계산을 확인합니다.
LLM 출력은 기록된 fixture로 교체하며 기본 테스트는 LLM 로그인이나 네트워크 없이 실행하는 것을 목표로 합니다.
초기 의존성 설치는 별도이며, 완전히 새로운 환경의 설치까지 오프라인이라고 표현하지 않습니다.

## 별도 smoke

PyreWire의 지원 환경 설치와 실제 재귀 질의를 초기 spike에서 확인합니다.
구독 인증 Codex의 작은 실제 추출·설명 호출은 사용자 실행을 전제로 명시적으로 opt-in합니다.
인증 실패, timeout, 비정상 종료와 잘못된 출력은 기록된 출력으로도 재현합니다.
세션 토큰이나 인증 파일을 테스트 fixture에 저장하지 않습니다.
합성 입력 전용 작업공간·읽기 전용 sandbox·불필요한 도구 제한을 실제 설정과 대조합니다.
문서가 파일 변경이나 추가 명령을 요구하는 smoke를 통해 거부 여부와 파일 불변을 확인합니다.
제한 강제를 확인하지 못한 live 경로는 미검증으로 남기고 자동으로 실행하지 않습니다.

## 비교 평가

같은 질문·문서에 대해 문서 검색만 하는 방식과 검토된 관계·규칙을 결합한 방식을 비교합니다.
정답 후보와 출처는 사람이 합성 자료에서 정하며, 평가 대상 LLM이 정답을 만들지 않습니다.
개발 사례와 최종 평가 사례를 분리합니다.
T09가 비교 평가를 담당합니다. T01에서 별도 holdout 질문 4개와 정답을 정하고,
평가 시 동일 입력의 검색-only와 규칙 결합 결과, 모델·입력 hash·호출 모드·결과를 함께 기록합니다.
기록 출력으로 한 비교와 실제 CLI 호출 비교를 구분하며, 실행하지 못한 비교를 완료로 표시하지 않습니다.

집합 정확도, 인용 일치, 잘못된 상태 혼입, 오류와 빈 결과 구분을 기록합니다.
T01에서 S1 후보 정확한 집합과 empty/error 구분을 확인했습니다. 별도 holdout은 `data/holdout/questions.json`의 4문항으로 고정했으며, 검색-only/규칙 결합 비교 측정은 아직 없습니다. 작은 사례의 성공을 전체 코드의 무결함이나 변경 안전성으로 일반화하지 않습니다.
